## 1. 产品全局结构

Globex 的前端是一个以"会话"为核心的单页应用，左侧导航 + 右侧内容区布局，共 7 个一级页面（来自 README 截图说明）。

```
┌──────────────┬──────────────────────────────────────────────┐
│   侧边导航    │                 内容区域                      │
│              │                                              │
│  🏠 首页     │   根据当前页面渲染不同内容                     │
│  💬 商品会话  │                                              │
│  ❤️  收藏    │                                              │
│  📦 订单     │                                              │
│  🧠 长期偏好  │                                              │
│  🔧 扩展/Skill│                                             │
│  🤖 自动化   │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

## 2. 页面详细说明

### 2.1 首页

**定位**: 产品门户 + 快速入口  
**核心内容**:
- 简单介绍 Globex 能做什么（3 个核心能力说明）
- 快速开始按钮 → 跳转到商品会话
- 近期会话列表（最近 3 条，带摘要）

**设计原则**: 0 门槛感知，用户打开就知道怎么用

---

### 2.2 商品会话（核心页面）

**定位**: 主交互界面，承载所有 AI 对话  
**布局**:

```
┌─────────────────────────────────────────────────────┐
│  会话标题   [当前模型]   [上下文压缩状态]             │
├─────────────────────────────────────────────────────┤
│                                                     │
│  [AI 消息气泡]  包含：                               │
│  - 文字回复（流式输出）                               │
│  - 商品卡片组（可展开/收起）                           │
│  - 确认单（创建订单 / 取消订单）                       │
│  - 任务计划面板（多步任务进展）                        │
│  - 澄清表单（动态问卷）                               │
│                                                     │
│  [用户消息气泡]                                      │
│                                                     │
├─────────────────────────────────────────────────────┤
│  [输入框]  [Skill 选择器]  [发送]                    │
└─────────────────────────────────────────────────────┘
```

**商品卡片设计规范**:

```
┌──────────────────────────────────────────┐
│  [商品主图]   商品名称                    │
│               品牌 · 型号                 │
│               ¥ 主显价格                 │
│               到手价明细：               │
│                 商品 ¥xxx               │
│                 运费 ¥xx                │
│                 关税 ¥xx (税率)          │
│                 合计 ¥xxx               │
│  [收藏]  [加入选购]                      │
└──────────────────────────────────────────┘
```

**确认单设计规范**:

```
┌──────────────────────────────────────────┐
│  ⚠️ 请核对以下信息后确认                  │
│                                          │
│  商品：[名称] x [数量]                   │
│  规格：[SKU 属性]                        │
│  收货：[地址]                            │
│  金额：¥xxx（仅商品价，不含运税）         │
│                                          │
│  [取消]           [确认下单]             │
└──────────────────────────────────────────┘
```

**设计原则**:
- Agent 回复流式输出，不等到完成才显示
- 商品卡多于 3 张时折叠，主显前 3 张
- 确认单按钮状态：未操作 → 已确认/已拒绝（不可撤销）

---

### 2.3 收藏

**定位**: 跨会话的商品收藏夹  
**功能**:
- 浏览收藏的商品
- 展示商品当前价格（价格已变动时提示）
- 快速进入会话继续讨论该商品

---

### 2.4 订单

**定位**: 本地订单账本  
**功能**:
- 订单列表（状态：待确认 / 已确认 / 已取消）
- 订单详情展开
- 对话式查询入口（"这个订单怎么样了"）

**状态流转**:
```
待确认（confirmation_pending）→ 已确认（CONFIRMED）→ 已取消（CANCELLED）
                              ↘ 已拒绝（declined）
```

> 无支付状态，无物流状态（本产品范围外）

---

### 2.5 长期偏好

**定位**: 用户自己管理 AI 对自己的了解  
**功能**:
- 查看所有已记录偏好（分 like / dislike 两类）
- 手动编辑偏好内容
- 手动删除偏好条目
- 偏好版本标注（每次修改有版本号，防止并发冲突）

**重要设计决策**:
- 偏好修改 / 删除需要二次确认（与 Agent 操作一致）
- dislike 条目用醒目颜色标注（因为它是硬约束）

---

### 2.6 扩展 / Skill

**定位**: 用户自定义选购规则  
**功能**:
- 查看系统内置 Skill 目录（只读）
- 创建个人 Skill（文本编辑器，Markdown）
- 为会话/自动化绑定指定 Skill
- Skill 版本管理（变更时提示重新绑定）

---

### 2.7 自动化

**定位**: 定时/定期选购助理  
**功能**:
- 创建自动化任务（模型 + Skill + 触发时间 + Prompt）
- 三类内置模板：每周推荐、接着比较、选购复盘
- 任务执行历史
- 暂停/删除任务

**创建自动化流程**:
```
选模板 → 选模型 → 选 Skill（可选）→ 设置触发时间 → 确认创建
```

## 3. 核心交互规范

### 3.1 流式输出

- AI 回复逐字流式显示，不等全文完成
- 工具调用期间显示"正在搜索商品…"等状态提示（tool.invoke 事件）
- 任务派发（多个子 Agent 并发）时显示任务面板（plan.update 事件）

### 3.2 错误处理

| 错误类型 | 用户侧呈现 |
|---------|----------|
| 模型超时/限流 | "正在重试…" + 最终失败提示 |
| 商品搜索无结果 | 如实告知，给出改条件重搜建议 |
| 工具不可用 | "XX 功能暂时无法使用，请稍后重试" |
| 超预算商品存在 | 说明"有但被价格约束挡住"，提供放宽建议 |

### 3.3 敏感操作必须页面确认

以下操作需要用户明确在 **页面** 点击按钮，不接受对话中的语言确认：

| 操作 | 说明 |
|------|------|
| 下单 | 确认单卡片上点击"确认下单" |
| 取消订单 | 取消确认单上点击"确认取消" |
| 写入偏好 | AgentScope 原生审批弹窗 |
| 修改偏好 | AgentScope 原生审批弹窗 |
| 删除偏好 | AgentScope 原生审批弹窗 |

## 4. 用户旅程地图

### 场景 A：新用户第一次跨境选购

```
[发现产品]
    │
    ▼
[首页感知能力]
    │ "这个 AI 能帮我选购跨境商品？"
    ▼
[描述需求]
    │ "想买个不含塑料的行李箱，预算 800，发到上海"
    ▼
[浏览候选商品]
    │ 流式出现商品卡，含到手价
    ▼
[追问：这个材质是什么？]
    │ Agent 引用商品卡字段回答，不编造
    ▼
[选定一款，发起下单]
    │
    ▼
[页面确认单]
    │ 核对商品/规格/地址/金额
    ▼
[点击确认下单]
    │ 订单状态：CONFIRMED
    ▼
[满意离开或继续浏览]
```

### 场景 B：老用户回访，偏好自动生效

```
[打开产品]
    │
    ▼
[新对话："再帮我找个旅行背包"]
    │ ← 系统在后台已注入 <buyer-preferences>：
    │    [dislike] 不要塑料材质
    │    [like] 日系简约风格
    ▼
[Agent 推荐只包含无塑料、日系风格商品]
    │ 用户无需再次说明偏好
    ▼
[用户："这次可以接受尼龙的"]
    │ Agent 记录为本轮临时要求，不写入长期记忆
    ▼
[推荐含尼龙商品，但注明"本轮临时放宽"]
```

### 场景 C：自动化定时任务

```
[用户配置自动化]
    │ 选模板：每周通勤好物
    │ 触发：每周一 10:00
    ▼
[周一 10:00 后台自动触发]
    │ 无需用户在场
    ▼
[Agent 执行选购任务]
    │ 搜索 → 生成清单 → 保存结果
    ▼
[用户下班后打开"自动化"页面]
    │ 查看本周推荐结果
    ▼
[感兴趣 → 进会话 → 继续讨论 → 可选下单]
```

## 5. 核心设计原则

1. **Agent 是助手，不是决策者**：所有涉及金钱的动作（下单/取消）必须人工页面确认
2. **信息来源透明**：价格来自工具返回，知识来自知识库，不编造
3. **偏好可控**：用户随时可以查看、修改、删除 Agent 对自己的了解
4. **渐进式信任**：新用户从简单查询开始，逐步建立对 Agent 能力的信任
5. **容错不消失**：工具失败时告知用户，给出可行替代，不让对话进入死胡同
6. **被过滤的也要告知**：有商品但被价格/材质约束挡住，必须告知用户"有但被挡了"，而不是说"没有"
