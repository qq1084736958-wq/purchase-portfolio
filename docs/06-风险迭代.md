## 1. 诚实的产品现状评估

> 本工程是**教学实战项目**，不是生产就绪的商业产品。

### 1.1 硬性限制（无法绕过）

| 限制 | 说明 | 对用户的影响 |
|-----|------|------------|
| 无真实商品供给 | 商品来自版本化样例目录 | 无法真正选购市面上的商品 |
| 无支付链路 | "订单"是本地意向账本 | 下单后无法实际付款 |
| 无物流跟踪 | 运费是估算，不连接物流系统 | 到手价仅供参考 |
| 无退货/售后 | 超出产品功能范围 | 用户完全期望无法满足 |

### 1.2 质量现状

| 维度 | 现状 | 目标 |
|-----|------|------|
| 安全契约 | 核心安全场景有 Harness 覆盖 | 全覆盖 |
| 召回效果 | 部分收益门禁尚未全部通过 | MRR 和 Recall@10 达标 |
| Reranker | 可选配，未配置时降级 | 生产必配 |
| Hybrid 召回 | 代码已实现，"冻结评测"不开启 | A/B 验证收益后开启 |
| 提示词缓存 | 基本保护（偏好不进 System Prompt） | Stable Prefix 实验验证 |

## 2. 产品风险矩阵

### 2.1 用户信任风险

**风险描述**：用户不确定 Agent 给的价格、库存、政策是否准确，不信任推荐

**根本原因**：
- 商品数据有时效性，不是实时价格
- 知识库内容有覆盖范围限制
- AI 推荐缺乏透明度

**缓解措施**（已有）：
- 所有数字来自工具返回，禁止编造
- 知识库政策类内容有置信度标注
- 商品卡展示原始检索数据，不加工

**待改进**：
- 加入"商品目录最后更新时间"展示
- 对于 AI 无把握的政策信息，引导用户自行核验

---

### 2.2 偏好管理风险

**风险描述**：Agent 误记/误删用户偏好，或偏好注入不准确导致错误推荐

**可能场景**：
- 把"这次想要轻一点的"（临时要求）记成长期偏好
- dislike 偏好因语义相似度不高被截断，漏了塑料排除
- 偏好版本冲突导致更新失败但 Agent 没有明确告知

**缓解措施**（已有）：
- 写/改/删操作需要原生审批，用户主动确认
- dislike 全量注入（不参与 top_k 截断）
- 版本冲突时返回最新列表要求重新确认
- 一次性要求不写入长期记忆（Prompt 约束）

**待改进**：
- 偏好页面展示"此偏好已影响 X 次检索"
- 定期推送"你有 X 条活跃偏好，要检查吗？"
- 偏好误记时的修正引导

---

### 2.3 材质过滤漏判风险

**风险描述**：用户设置"不要塑料"，推荐结果仍含合成聚合物商品

**高风险场景**：
- "再生尼龙"被错误标为"环保无塑料"
- 材质词别名未覆盖（如"RPET"属合成聚合物但名字不含"塑料"）
- 偏好在 top_k 截断中丢失（但现在已强制全量保留 dislike）

**缓解措施**（已有）：
- dislike 全量保留，不参与截断
- `material_exclusion_tags` 函数维护材质别名词典
- Prompt 明确"再生尼龙仍是合成聚合物"
- Harness 安全契约覆盖（0 误放行门禁）

**待改进**：
- 扩展材质别名词典（目前仅 5 大类）
- 对材质标注缺失的商品，保守策略（告知不确定而非随机推荐）

---

### 2.4 上下文丢失风险

**风险描述**：长对话后，重要的用户需求被压缩摘要处理后遗失

**触发条件**：对话 token 数超过 TARGET_TOKENS（48k）

**缓解措施**（已有）：
- 近期 N 轮完整保留，只压缩旧轮次
- dislike 偏好不参与截断
- `context.compressed` 通知用户

**待改进**：
- 压缩后明确告知用户"早期内容已摘要，重要偏好已保留，若有疑问可重新告知"
- 支持用户手动标记"这条消息很重要，不要压缩"

---

### 2.5 自动化任务异常风险

**风险描述**：自动化任务执行时模型配置过期，或 Skill 已更新，静默执行旧版本

**缓解措施**（已有）：
- 触发时重新校验模型版本和 Skill 版本
- 版本不匹配时标记失败，不继续执行
- 待处理确认单存在时，自动化不执行写操作

**待改进**：
- 失败通知主动推送给用户（而不是只记录日志）

## 3. 优先级与迭代规划

### Phase 1（当前工程已有）

```
✅ 自然语言商品检索（embedding + rerank）
✅ 到手价计算（运费 + 关税估算）
✅ 长期偏好记忆（跨会话）
✅ 下单安全二次确认
✅ 多轮对话持久化（服务重启可恢复）
✅ Harness 安全评测框架（48 场景）
✅ 多 Agent 编排（主Agent + 检索 + 交易）
✅ 上下文管理（压缩 + 偏好注入优化）
✅ 自动化定时任务（3 类内置模板）
✅ 个人 Skill 扩展
✅ 澄清表单
✅ Prompt Cache 保护
```

### Phase 2（近期优化，低成本高收益）

```
□ 偏好使用统计（影响了多少次检索，在偏好页展示）
□ 知识库内容扩充（更多品类、更多跨境政策）
□ 商品卡增强（规格对比表、多图浏览）
□ 压缩通知 UX 改善（告知用户具体保留了什么）
□ 自动化失败主动通知用户
□ 材质别名词典扩展
```

### Phase 3（中期，需要工程投入）

```
□ Hybrid 召回开启（BM25 + 向量融合，待 A/B 数据）
□ Reranker 效果评测完整闭环
□ Prompt Cache Stable Prefix 实验（CONTEXT_PROMPT_LAYOUT）
□ 学习发件箱（正向行为捕获，离线提炼偏好）
□ 多模型 A/B 测试闭环
□ 跨语言检索增强（EN/JP 商品中文查询）
```

### Phase 4（商业化方向，重大投入）

```
□ 真实商品供给接入（商家 API 对接）
□ 支付链路集成
□ 实时物流状态追踪
□ 跨境合规实时核验（禁运品/关税税率实时数据库）
□ 多语言用户扩展（英文/日文/韩文界面和对话）
□ 商家侧工具（选品分析、价格策略建议）
□ 企业采购功能（多收货地、审批流程）
```

## 4. 核心产品指标框架

### 4.1 用户体验指标

| 指标 | 定义 | 参考目标 |
|-----|------|---------|
| 检索满意率 | 用户在推荐中发起下单/收藏的比例 | > 30% |
| dislike 零漏率 | 推荐商品不违反 dislike 偏好的比例 | 100%（硬底线） |
| 确认单转化率 | 确认单出现后用户最终确认的比例 | > 50% |
| 澄清完成率 | 表单出现后用户填完的比例 | > 60% |
| 自动化续用率 | 配置自动化后次月仍活跃的比例 | > 70% |

### 4.2 系统健康指标

| 指标 | 定义 | 参考目标 |
|-----|------|---------|
| 首字延迟 P95 | 95% 请求的首字输出时间 | < 3s |
| 端到端延迟 P95 | 95% 请求的完整响应时间 | 取决于模型 |
| 会话恢复率 | 服务重启后成功恢复的会话比例 | > 99% |
| 工具错误率 | 工具调用失败比例 | < 1% |
| 平均 Token 消耗 | 单次完整交互的 Token 数 | 持续优化，对比基线 |

### 4.3 Harness 质量门禁

| 门禁 | 通过条件 | 当前状态 |
|-----|---------|---------|
| 材质安全 | 0 误放行 | ✅ 覆盖中 |
| 价格约束安全 | 0 误放行 | ✅ 覆盖中 |
| 下单安全 | 0 误放行 | ✅ 覆盖中 |
| 偏好审批安全 | 0 违规 | ✅ 覆盖中 |
| Recall@10 | 待定基准后明确 | 🔄 评测中 |
| Token 成本 | 不超基线 × 1.1 | 🔄 评测中 |
| 延迟 P95 | 待定 | 🔄 评测中 |

## 5. 给各角色的下一步建议

### 对产品负责人

1. **明确商业模式**：SaaS 工具 vs 平台入口 vs 商家插件？决定了供给侧接入策略
2. **真实用户测试**：当前评测基于合成场景，需要真实用户行为数据验证召回效果
3. **知识库内容规划**：品类知识库是检索质量的护城河，需要持续内容投入

### 对技术团队

1. **打通 Reranker 效果评测**：当前降级状态有质量损失，优先定量验证
2. **Hybrid 召回 A/B 实验**：代码已就绪，缺的是有效对照实验数据
3. **Prompt 灰度发布机制**：提示词变更影响全量用户，建议按 buyer_id 分流

### 对运营团队

1. **建立用户反馈闭环**：对话结束后加入评分入口，识别低质量推荐
2. **偏好数据分析**：统计最常记录的偏好类型，指导功能优化
3. **自动化模板扩充**：内置 3 个模板覆盖面有限，基于用户行为数据扩充
