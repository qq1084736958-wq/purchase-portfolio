## 2. 四层架构详解

### 2.1 接口层（Presentation Layer）

**技术栈**：FastAPI + Uvicorn

**核心端点**：

| 端点 | 方式 | 功能 |
|------|------|------|
| `/commerce/ag-ui/run` | POST → SSE | AG-UI 主交互入口，返回流式事件 |
| `/commerce/confirmations` | GET / POST | 查询/执行下单或取消确认 |
| `/commerce/confirmations/{id}` | POST | 执行特定确认操作 |
| `/buyer/preferences` | GET / POST / DELETE | 偏好 CRUD |
| `/automations` | GET / POST / PUT / DELETE | 自动化任务管理 |
| `/buyer/skills` | GET / POST | 个人 Skill 管理 |
| `/model-workspace` | GET / POST | 模型档位选择 |
| `/context-workspace` | GET | 上下文状态查询 |
| `/health` | GET | 服务健康检查 |

**AG-UI 事件类型**（SSE 推送给前端的事件）：

```
token.delta       → 流式文字片段（逐字推送）
tool.invoke       → 工具调用开始（显示"正在搜索..."）
tool.result       → 工具调用结果（商品卡数据）
plan.update       → 任务计划更新（多步任务面板）
context.compressed→ 上下文已压缩通知
order.confirmed   → 订单确认成功
error             → 错误通知（脱敏）
final.result      → 本轮完整最终回复
```

### 2.2 应用层（Application Layer）

**核心组件职责**：

| 组件 | 文件 | 职责 |
|-----|------|------|
| `MainAgentOrchestrator` | `orchestrator.py` | 会话恢复、偏好注入、事件映射、重试、持久化 |
| `MainAgentFactory` | `main_agent.py` | 构建 MainAgent（工具集 + 中间件 + Prompt 组装） |
| `SessionRegistry` | `main_agent.py` | 按会话 ID 缓存 Agent，多轮对话恢复 |
| `SearchAgentFactory` | `search_agent.py` | 按需构建检索子 Agent |
| `TradeAgentFactory` | `trade_agent.py` | 按需构建交易子 Agent |
| `AGUIRuntime` | `agent_runtime.py` | 运行租约管理、日志、过期处理 |
| `AutomationService` | `automation.py` | 自动化任务验证与执行 |
| `PreferenceSelector` | `memory/preference_selector.py` | 偏好筛选注入策略 |

**工具调用中间件洋葱模型**：

```
工具调用请求
     │
     ▼ （外层先进入）
HarnessToolMiddleware
  · SequencingTracker（顺序检查）
  · LoopDetector（循环检测）
     │
     ▼
ToolResilienceMiddleware
  · CircuitBreaker（熔断）
  · Timeout（超时保护）
     │
     ▼
实际工具函数执行
     │
     ▼ （逆序穿出）
（返回中间件处理）
```

**并发安全机制**：

```
同一进程内：asyncio.Lock（会话级别）
跨进程：数据库 CAS（乐观锁，revision 比较）
失败处理：丢弃本地缓存，下次从持久化重新读取
```

**设计模式**：六边形架构（Ports & Adapters）

**核心领域对象**：

### 2.4 基础设施层（Infrastructure Layer）

**外部服务接入**：

| 服务 | 配置参数 | 用途 | 降级策略 |
|-----|---------|------|---------|
| LLM 网关 | `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | Agent 推理 | 切换 Fallback 模型 |
| Embedding | `EMBEDDING_MODEL`（复用 LLM 网关） | 向量化查询和偏好 | 不可降级（必须有） |
| Qdrant | `QDRANT_URL`（空=本地嵌入模式） | 商品向量检索 | 本地嵌入（开发默认） |
| Reranker | `RERANKER_BASE_URL` | 二阶段精排 | 按向量分排序（自动降级） |
| Redis | `REDIS_URL` | 任务队列、跨进程事件 | 不启用（开发默认） |
| Langfuse | `LANGFUSE_*` | 全链路 Trace | 不启用（开发默认） |
| Tavily | `TAVILY_API_KEY` | Web 搜索工具 | 不注册 web_search_tool |

**本地持久化（默认 SQLite）**：

| 数据 | 存储位置 |
|-----|---------|
| 订单账本 | `DATA_DIR/trade.db` |
| 会话状态（AgentState） | `DATA_DIR/sessions.db` |
| 长期偏好 | `DATA_DIR/buyer_memory.db` |
| 模型档位 | `DATA_DIR/models.sqlite3` |
| 商品向量索引 | `DATA_DIR/qdrant/` |
| 运行日志（AG-UI） | `DATA_DIR/ag_ui_journal/` |

## 3. 数据流向

### 3.1 一次完整选购请求（端到端）

```
[Step 1] 用户 → POST /commerce/ag-ui/run
  Body: { session_id, buyer_id, message: "买行李箱不含塑料800内" }

[Step 2] Orchestrator 准备上下文
  · 设置 ShoppingContext ContextVar（session_id, buyer_id, locale, currency）
  · 从 SQLite 恢复 AgentState（对话历史）
  · 读取 BuyerPreference，运行 PreferenceSelector
  · 有变化 → 构造 <buyer-preferences> hint 消息注入

[Step 3] MainAgent 推理（LLM Call 1）
  Input: [System Prompt] + [hint] + [对话历史] + [用户消息]
  Output: tool_calls: [product_search_tool({
    normalized_query: "行李箱 轻便",
    ship_to: "CN",
    price_max_major: 800,
    excluded_material_tags: ["合成聚合物"]
  })]

[Step 4] CatalogSearchUseCase 执行
  · text-embedding-v4 向量化 → [0.12, -0.34, ...]
  · Qdrant ANN 召回 top-32
  · 硬约束过滤（price/ship_to/material）
  · Reranker 精排
  · 到手价计算（运费 + 关税估算）

[Step 5] 工具结果返回 JSON
  { hits: [10条], filtered_out: [3条超预算], notes: "..." }

[Step 6] MainAgent 推理（LLM Call 2）
  基于工具结果生成自然语言回复

[Step 7] 流式推送到前端（SSE）
  token.delta × N → 逐字显示回复
  tool.result → 前端渲染商品卡
  final.result → 本轮完成

[Step 8] AgentState 持久化 → SQLite
```

### 3.2 商品索引数据流

```
商品目录（YAML/CSV 样例数据）
  │ 离线处理
  ▼
Embedding 批量向量化
  │
  ▼
Qdrant 向量存储
  │ 同时维护
  ▼
内存商品仓（ProductInMemoryRepository）
  · 快速精确查询 product_id / sku_id
  · 价格/库存的权威来源
```

## 4. 部署模式

### 4.1 开发模式（本机）

```
Terminal 1：
  uv run uvicorn app.presentation.server:create_app --port 8000

Terminal 2：
  npm --prefix frontend run dev（localhost:3000）

依赖：
  · Python 3.11-3.13 + uv
  · Node.js 22 + npm
  · 模型网关（DashScope / OpenAI 兼容）
  · Qdrant 自动本地嵌入（无需安装）
```

### 4.2 Docker Compose 模式

```yaml
services:
  frontend:   nginx 静态服务（Node.js 构建产物）
  api:        FastAPI + uvicorn（端口 8000）
  worker:     Redis 队列消费者（可选）
  redis:      Redis（端口 6379）
  qdrant:     Qdrant（端口 6333）

卷（持久化）：
  ./data → API 容器的 DATA_DIR
  qdrant_data → Qdrant 数据
```

### 4.3 环境变量关键配置

| 变量 | 必填 | 说明 |
|-----|------|------|
| `LLM_BASE_URL` | ✓ | LLM 网关地址 |
| `LLM_API_KEY` | ✓ | LLM API 密钥 |
| `LLM_MODEL` | ✓ | 主模型名（如 qwen3-max） |
| `EMBEDDING_MODEL` | ✓ | Embedding 模型名 |
| `DATA_DIR` | - | 数据目录（默认 ./data） |
| `QDRANT_URL` | - | 空则本地嵌入模式 |
| `RERANKER_BASE_URL` | - | 空则向量分降级 |
| `TAVILY_API_KEY` | - | 空则不注册联网工具 |

## 5. 可观测性设计

### 5.1 追踪（Tracing）

支持 OpenTelemetry 标准，可导出到 Langfuse：

```
一次请求的 Trace 树（简化）：

ag-ui-run（根 Span）
  └── orchestrator.handle_intent
        ├── preference.inject（偏好注入）
        ├── agent.reply（主 Agent 推理）
        │     ├── llm.call（LLM 调用 1）
        │     ├── tool.invoke: product_search_tool
        │     │     ├── embedding.encode
        │     │     ├── qdrant.search
        │     │     └── reranker.rerank
        │     └── llm.call（LLM 调用 2，生成回复）
        └── session.persist（状态持久化）
```

追踪配置：
```
有 OTEL_EXPORTER_OTLP_ENDPOINT → 走 OTLP 导出
有 LANGFUSE_* → 自动启用 Langfuse Basic Auth v4
两者都没有 → 不启用追踪（开发模式默认）
```

### 5.2 运营指标（OperationalMetrics）

| 指标名 | 说明 |
|-------|------|
| `request_count` | 请求总数（按 status 分组：success/error/cancelled） |
| `request_latency` | 端到端延迟分布 |
| `llm_token_usage` | 每请求 Token 消耗（input + output） |
| `tool_error_rate` | 工具失败率（按工具名分组） |
| `context_compression_rate` | 上下文压缩触发率 |

指标读取权限：需要配置 `METRICS_READER_BUYERS` 且 `IDENTITY_MODE=hmac`

## 6. 安全设计

### 6.1 身份认证

| 模式 | 说明 | 适用场景 |
|-----|------|---------|
| `demo` | 客户端声明身份（默认） | 本地开发/演示 |
| `hmac` | 服务端签名验证 | 生产部署 |

`SESSION_OWNER_BINDING=1`（默认开启）：会话 owner 绑定，防止跨 buyer 的会话访问。

### 6.2 模型凭据安全

- 凭据使用 Fernet 对称加密存储
- 主密钥（`MODEL_MASTER_KEY`）仅通过服务端环境变量注入
- 不写入 `.env`，不进代码仓库，不打印到日志

### 6.3 输出安全（L4 审核）

```
输出审核在最终回复推送前执行：
  · 检测内部信息（session_id、内部路径、密钥片段等）
  · 命中时脱敏处理（不阻断回复，避免误判让整轮失败）
  · 同时发布一条 error 事件告警
```

## 7. 技术选型决策记录

| 决策点 | 选择 | 未选原因 |
|-------|------|---------|
| Agent 框架 | AgentScope 2.0 | LangChain: 重; AutoGen: 不如 AS 的 State 管理 |
| 流式协议 | AG-UI + SSE | WebSocket: 双向不必要; 普通 HTTP: 无法流式 |
| 向量库 | Qdrant | Pinecone: 云绑定贵; Weaviate: 复杂 |
| 关系存储 | SQLite | PostgreSQL: 开发环境依赖重 |
| 提示词管理 | YAML 文件 | DB 存储: 难 diff 和版本控制 |
| 偏好注入 | hint 消息 | System Prompt: 破坏 Prompt Cache 命中率 |
| 凭据加密 | Fernet | 明文 env: 安全风险 |

## 8. 关键技术约束汇总

| 约束 | 说明 |
|-----|------|
| Python 版本 | 3.11–3.13（pyproject.toml 约束） |
| Node.js 版本 | 22（与 Docker 前端构建一致） |
| LLM 协议 | 必须支持 OpenAI 兼容协议 + 工具调用 + 流式输出 |
| 本地 Qdrant 限制 | 嵌入模式仅支持单进程（自动化 worker 需 external 模式 + 独立 Qdrant） |
| 会话并发 | 同会话同进程 asyncio.Lock + 跨进程 CAS |
| 商品数据 | 只有课程样例目录，不是真实电商供给 |
