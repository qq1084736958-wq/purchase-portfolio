# 产品需求文档（PRD）

**产品名称**: Globex 跨境选购 Agent  
**文档版本**: v1.0  
**日期**: 2026-10-25  
**状态**: 参考版本（对照课程工程）

---

## 1. 产品背景与定位

### 1.1 背景

跨境电商的消费决策成本远高于国内购物：用户需要同时处理多语言信息、汇率换算、关税估算、材质合规（如某些国家对材料的限制）、收货国运费差异等问题。传统搜索框无法理解这些复合意图，导致大量用户在选品阶段放弃。

### 1.2 产品定位

> **Globex 是一个具备长期记忆的跨境购物 AI 助理。**

它的核心差异点不是"更好的搜索"，而是：

- **听懂人话**：自然语言描述需求，不需要学平台搜索语法
- **帮你算账**：到手价 = 商品价 + 运费 + 关税，直接给结论
- **记住你**：材质偏好（不要塑料）、风格偏好跨会话保留
- **引导决策**：不只给清单，给选择理由和差异说明
- **安全下单**：所有下单操作需人工二次确认，Agent 不自动执行

### 1.3 目标用户

| 用户类型 | 描述 | 核心痛点 |
|---------|------|---------|
| **跨境精品消费者** | 25-45 岁，有特定品质需求（无塑料、日系风格等），购物频率中高 | 跨境规则复杂，怕买错 |
| **轻量跨境买家** | 偶尔海外购，不熟悉平台规则 | 不懂怎么算到手价，担心关税超预期 |
| **礼品采购者** | 需要在特定预算和收货地点内快速找到合适礼物 | 筛选条件多，需要推荐理由 |

## 2. 功能范围

### 2.1 核心功能模块

#### F1：自然语言商品检索

**用户故事**：
- 作为买家，我想用自然语言描述想要的商品（包括用途、材质、预算、收货地），系统能返回符合条件的候选清单

**验收标准**：
- 输入含预算硬约束时（"500 以内"），候选商品价格均不超过该上限
- 输入含收货地时（"发到上海"），商品卡内联到手价（含运费+关税估算）
- 输入含材质排除时（"不要塑料"），命中 dislike 的商品不出现在候选中，并在说明中注明
- 候选不足 3 条时，系统自动改写查询词再召回一次
- 返回商品按 product_id 维度，不重复、不伪造

**优先级**: P0（必须有）

---

#### F2：品类知识问答

**用户故事**：
- 作为买家，我想在选购前了解"这个品类怎么挑"、"这个价格合理吗"、"有什么坑"，不用去查攻略

**验收标准**：
- 买家问"怎么挑"类问题时，系统先从知识库召回选购常识，再给商品推荐
- 知识库中政策类字段（关税税率、免税额度）标注数据状态，若不是"权威来源"不得以确定语气告知用户
- 知识库回答不能替代商品推荐，询问选购时必须同时给出具体商品

**优先级**: P1（应有）

---

#### F3：订单意向管理

**用户故事**：
- 作为买家，我想在 Agent 协助下准备下单，但我需要在页面上看到完整确认单并手动确认后才生效

**验收标准**：
- create_order_tool 只准备确认单，不直接写入订单
- 页面呈现确认卡（商品、规格、数量、地址、金额）
- 用户点击"确认"按钮后才执行写入
- Agent 不得将用户在对话中说的"确认"/"同意"当作页面确认动作
- 取消订单前必须先查询订单状态，仅 CONFIRMED 状态可取消
- 不支持支付、物流跟踪，不得向用户承诺这些能力

**优先级**: P0

---

#### F4：长期偏好记忆

**用户故事**：
- 作为买家，我想告诉 Agent 我的长期偏好（不要塑料、喜欢日系简约），下次打开新会话时它还记得

**验收标准**：
- 用户明确说"帮我记住…"时调用记忆写入工具
- 写入/修改/删除操作需经 AgentScope 原生审批，用户拒绝后不得重试绕过
- dislike 类偏好（材质禁忌等）作为硬约束，全量注入每次检索
- like 类偏好（风格喜好）按本轮语义相关性排序，取 top_k 注入
- 一次性临时要求不写入长期记忆
- 用户说"以后不用避开塑料了"时，从记忆中撤回该条

**优先级**: P1

---

#### F5：澄清表单（选购条件收集）

**用户故事**：
- 作为买家，当我的需求描述不够完整时，我希望 Agent 通过结构化问卷引导我补充关键信息

**验收标准**：
- 仅在"缺少影响选择的关键条件"或"买家明确要求表单"时调用
- 表单字段由 Agent 根据本轮上下文动态生成，非固定模板
- 预算问题必须说明币种、数量及是否含税运
- 不为用户预选答案，允许留空或选"不确定"
- 表单提交后以新买家消息的形式继续对话

**优先级**: P1

---

#### F6：自动化任务

**用户故事**：
- 作为买家，我想配置定期执行的选购任务，例如"每周一帮我找一下通勤包新款"

**验收标准**：
- 支持按 weekday + time 定时触发
- 支持三类内置模板：每周推荐、接着上次比较、选购进展复盘
- 模型配置变更后旧自动化须重新确认
- Skill 内容更新后旧绑定失效
- 待处理的交易确认单存在时，自动化不得执行写操作

**优先级**: P2（增值功能）

---

#### F7：个人 Skill 扩展

**用户故事**：
- 作为买家，我想自定义选购规则（如"我出差时只看能登机的箱子"），Agent 在相关场景主动应用

**验收标准**：
- 支持在页面直接编写和保存个人 Skill
- Skill 版本变更时需重新绑定到自动化
- Skill 注入不影响 Prompt Cache 命中率（append_only 模式）

**优先级**: P2

---

### 2.2 非功能性需求

| 维度 | 要求 |
|------|------|
| **响应速度** | 首字延迟 < 3s（含模型启动），全文流式输出 |
| **会话持久化** | 服务重启后多轮对话可恢复 |
| **并发安全** | 同一会话同进程加锁，跨进程通过 CAS 防写冲突 |
| **上下文管理** | 超长对话自动压缩摘要，近期轮次优先保留 |
| **安全** | 输出审核（L4 脱敏），不暴露内部 ID、密钥 |
| **可观测** | 支持 OpenTelemetry + Langfuse 全链路 Trace |
| **多语言** | 回复语言对齐买家 locale，默认中文 |

---

## 3. 明确不做的事项（Out of Scope）

- **实际支付**：本产品不集成支付链路，不处理资金流
- **真实物流**：不追踪快递状态，不承诺发货时效
- **商家侧功能**：无商品管理、库存管理、商家入驻
- **比价多平台**：只检索 Globex 自有目录商品
- **退货/售后**：暂不在 Agent 支持范围内

## 4. 验收门禁说明

根据项目 Harness 评测框架，以下场景有自动化质量门禁：

| 场景 | 门禁类型 |
|------|---------|
| 材质 dislike 排除 | 安全契约（0 误放行） |
| 价格约束过滤 | 安全契约 |
| 下单不代替用户确认 | 安全契约 |
| 偏好写入需原生审批 | 安全契约 |
| 商品信息不伪造 | 确定性契约 |
| 召回率 / MRR | 收益指标（效果门禁） |
| Token 消耗 | 成本门禁 |

> 注意：当前版本部分收益门禁尚未全部通过，工程处于"教学实战"阶段，不代表生产就绪状态。
