## 流程 1：自然语言选购主流程

### 1.1 整体流程

```
┌──────────────────┐
│  用户发送消息     │
│  "想买个行李箱，  │
│   不含塑料，800内"│
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│ Orchestrator     │
│ · 设置会话上下文  │
│ · 读取长期偏好    │
│ · 注入偏好 hint  │
│   (如有变化)     │
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  MainAgent 推理  │
│  (AgentScope 2.0)│
│  ReAct: max 15轮 │
└────────┬─────────┘
         │
    ┌────┴────┐
    │简单任务？│
    └────┬────┘
    Yes  │  No（可并行 / 上下文隔离 / 调用链深）
    │    │  │
    │    │  └→ task_dispatch（一次性发起多个）
    │    │       ├→ SearchAgent
    │    │       └→ TradeAgent（如需）
    │    │             │（并发执行）
    └────┘─────────────┘
         │ 整合结果
         ▼
┌──────────────────┐
│  生成最终回复     │
│  · 文字推荐理由  │
│  · 商品卡数据    │
│  · 流式输出      │
└────────┬─────────┘
         │ SSE 事件流
         ▼
┌──────────────────┐
│  前端渲染         │
│  · 文字逐字显示  │
│  · 商品卡出现    │
│  · 任务面板更新  │
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  持久化会话状态   │
│  AgentState → DB │
└──────────────────┘
```

### 1.2 商品检索内部流程（SearchAgent 执行）

```
收到 demands（自然语言需求）
         │
    ┌────┴─────────────────────┐
    │需要选购常识？              │
    │（用户问"怎么挑"/"多少合理"）│
    └────┬─────────────────────┘
    Yes  │  No
    │    │
    ▼    │
category_insight_tool
    │ 获取：属性口径、价格区间、避坑点
    │
    └→（汇入）
         │
         ▼
改写 normalized_query
提取槽位：
  ship_to / price_max_major / excluded_material_tags
         │
         ▼
product_search_tool 调用：
  ① Embedding 向量化 query
  ② Qdrant ANN 召回 top-32
  ③ （可选）BM25 词法召回 + RRF 融合
  ④ 硬约束过滤：
       price <= price_max_major
       ship_to 可达
       material 不在 excluded_material_tags
  ⑤ Reranker 精排（可选，降级为向量分排序）
  ⑥ 计算 landed_price（ship_to 有值时）
         │
    ┌────┴──────────┐
    │ 候选 < 3 条？  │
    └────┬──────────┘
    Yes  │  No
    │    │
    ▼    │
改写扩展 query
再调一次 product_search_tool
    │
    └→（汇入）
         │
         ▼
按偏好筛选：
  dislike → 硬排除（不进 hits，进 filtered_out）
  like    → 排序加权
         │
         ▼
返回 JSON：
{
  "hits": [...],         ← 最终推荐候选
  "filtered_out": [...], ← 被约束挡掉的候选（含挡住原因）
  "notes": "..."         ← 筛选说明
}
```

### 1.3 到手价展示规则

| 场景 | 商品卡展示 |
|------|---------|
| 无 ship_to | 仅显示商品单价（主显价） |
| 有 ship_to | 内联 landed_price：商品价 + 运费 + 关税 + 合计 |

**Agent 规则**：直接引用 landed_price，不自行计算；商品卡是单件报价，不得当多件总价用。

## 流程 2：下单确认流程

```
用户表达购买意愿
"帮我买那个行李箱，发到上海 XXX 路"
         │
         ▼
MainAgent 核验前置条件：
  ✓ 当前会话有该商品的检索记录？
  ✓ product_id + sku_id + quantity 齐全？
  ✓ shipping_address 有？
         │
  缺信息 → 追问（不编造地址）
  齐全 ↓
         ▼
调用 create_order_tool：
  准备确认单（不执行写入）
  返回：
    confirmation_required: true
    confirmation: {
      items, shipping_address, amount, currency
    }
         │
         ▼
Agent 回复：
  "请核对页面确认单并点击确认"
         │
         ▼
前端展示确认单卡片：
  ┌──────────────────────────────┐
  │ ⚠️ 请核对后确认              │
  │ 商品：行李箱 × 1             │
  │ 规格：20寸 · 黑色            │
  │ 收货：上海 XXX 路             │
  │ 金额：¥499（仅商品价）        │
  │ [取消]      [确认下单]       │
  └──────────────────────────────┘
         │
    ┌────┴────────────┐
    │ 用户点击？       │
    └────┬────────────┘
    取消  │  确认下单
    │    │
    ▼    ▼
  对话   POST /commerce/confirmations/{id}
  继续     │
           ▼
         订单状态：CONFIRMED
         推送 order.confirmed 事件
         前端订单页更新
```

**安全控制**：
- ❌ 用户在对话说"确认" → 不执行写入
- ❌ Agent 说"用户确认了" → 不执行写入
- ✅ 只有页面按钮点击 → 执行写入

## 流程 3：取消订单流程

```
用户："取消 ORDER-001"
         │
         ▼
Agent 调用 query_order_tool(order_id)
核验订单状态
         │
    ┌────┴──────────────────┐
    │ 订单状态               │
    └────┬──────────────────┘
         │
  CONFIRMED ↓   CANCELLED → 告知已取消
                其他状态  → 告知当前状态，无法取消
         ▼
调用 cancel_order_tool：
  准备取消确认单（不执行取消）
  返回：
    confirmation_required: true
    confirmation: { order summary, reason }
         │
         ▼
前端展示取消确认单
         │
    用户点击"确认取消"
         │
         ▼
POST /commerce/confirmations/{id}
订单状态：CANCELLED
```

## 流程 4：偏好记忆管理流程

### 4.1 新增偏好

```
用户明确说：
"帮我记住，我不要任何塑料材质的商品"
         │
         ▼
Agent 判断：
  是长期稳定偏好？（不是"这次…"这类一次性要求）
         │ Yes
         ▼
调用 remember_preference_tool(
  kind="dislike",
  statement="不要任何塑料材质"
)
         │
         ▼
⚠️ AgentScope 原生审批触发
前端展示审批弹窗：
  "是否同意记录以下偏好？
   [dislike] 不要任何塑料材质"
  [拒绝]  [同意]
         │
    ┌────┴────┐
    │ 用户操作 │
    └────┬────┘
    拒绝  │  同意
    │    │
    ▼    ▼
  取消  偏好写入数据库
  不重试  memory_id + version 分配
         下次会话开始时注入偏好 hint
```

### 4.2 修改偏好

```
用户说："把'不要塑料'改成'不要一次性塑料'"
         │
         ▼
Agent 从当前 <buyer-preferences> 中
找到精确的 memory_id 和 version
         │
         ▼
调用 update_preference_tool(
  previous_statement="不要任何塑料材质",
  kind="dislike",
  statement="不要一次性塑料",
  memory_id="abc123",
  expected_version=2
)
         │
    ┌────┴──────────────┐
    │ 版本校验           │
    └────┬──────────────┘
    不一致 → 返回最新列表
            要求 Agent 重新确认后操作
    一致 ↓
         ▼
⚠️ 原生审批 → 用户确认
原子替换旧偏好
```

### 4.3 撤回偏好

```
用户说："以后不用避开塑料了"
         │
         ▼
Agent 从 <buyer-preferences> 找到对应条目
（必须精确匹配，不按语义相似猜）
         │
调用 forget_preference_tool(
  statement="不要任何塑料材质",
  memory_id="abc123",
  expected_version=2
)
         │
⚠️ 原生审批 → 用户确认
从数据库中删除该条偏好
```

### 4.4 偏好注入时机

```
每轮对话开始前：

PreferenceSelector.select(
  preferences=全量偏好,
  query=本轮用户输入,
  top_k=5
)
         │
         ▼
筛选策略：
  [dislike] → 全量保留，不截断
  [like]    → 按语义相似度排序，取 top_k
         │
         ▼
与上轮注入内容对比：
  有变化 → 注入 <buyer-preferences> hint
  无变化 → 跳过（节省 Token）
```

## 流程 5：澄清表单流程

### 何时触发

```
条件 A: 缺少"影响选择的关键条件"
  例：用户只说"帮我买个包"，没说预算/收货地/用途
  
条件 B: 买家明确要求填表
  例："帮我填个表说一下我的需求"
```

### 流程

```
Agent 判断需要澄清
         │
         ▼
Agent 动态生成表单结构：
  问题内容 / 顺序 / 类型（文本/单选/多选）
  选项（如有）/ 是否必填 / 提示说明
         │
  规则：只问相关未知信息
       不重复已知信息
       不替用户预选
       预算问题必须说明币种+是否含税运
         │
         ▼
调用 show_shopping_form(questions=[...])
前端渲染问卷组件
         │
用户填写后提交
         │
         ▼
表单内容作为新用户消息进入对话
Agent 基于完整信息重新检索推荐
         │
注意：表单不写长期记忆
     表单不批准任何记忆/订单操作
```

## 流程 6：自动化任务执行流程

### 6.1 配置自动化

```
用户在自动化页面操作：
         │
         ▼
选择模板 / 自定义设置
  · 触发时间（weekday + time）
  · 绑定模型档位
  · 绑定 Skill（可选）
  · 选购 Prompt
         │
         ▼
POST /automations/save
  Server 验证：
    ✓ 模型配置版本匹配（防旧配置静默延续）
    ✓ Skill 版本可用
  验证通过 → 保存自动化定义
```

### 6.2 定时触发与执行

```
定时器触发（如每周一 10:00）
         │
         ▼
读取自动化定义
         │
         ▼
Server 校验：
  ✓ 模型配置版本仍匹配？
  ✓ Skill 仍可用？
  ✓ 目标会话有待处理确认单？
         │
  校验失败 → 标记失败，记录日志
  校验通过 ↓
         │
         ▼
构建 SubmitIntentInput：
  · shopping_session_id = 绑定会话
  · buyer_id = 用户 ID
  · selected_skill = 绑定 Skill
  · raw_query = 自动化 Prompt
         │
         ▼
调用 MainAgentOrchestrator.handle_intent()
（与用户手动输入走同一条主链路）
         │
         ▼
执行完成 → 结果保存到任务历史
         │
用户查看"自动化"页面
  → 查看本次执行结果
  → 可进入关联会话继续讨论
  → 可选择下单（需页面确认）
```

### 6.3 自动化安全边界

```
✓ 允许：搜索商品、整理清单、记录进展
✗ 不允许：代替用户点击确认下单
✗ 不允许：当前会话有待处理确认单时执行任何写操作
```

## 流程 7：上下文压缩流程

```
每轮对话结束后检测：
         │
         ▼
当前上下文 Token 数 > TARGET_TOKENS (48k)?
         │
    No   │  Yes
    │    │
    不压缩  触发压缩
         │
         ▼
识别"旧轮次"（距当前较远的交互）
         │
         ▼
生成摘要（保留：关键决策、商品选择、偏好信息）
         │
         ▼
摘要替换原始消息
释放 Token 空间
         │
         ▼
检测：AgentState.summary 发生变化？
         │ Yes
         ▼
发布 context.compressed 事件
前端显示压缩通知
```
